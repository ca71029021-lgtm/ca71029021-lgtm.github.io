# AGENTS.md — правила AI-агента проекта ALTAY CEDAR / Siberian Nature Style

## Проект
Премиальный одностраничный сайт производителя эксклюзивной мебели из цельных слэбов алтайского кедра. Стек: React 18 + TypeScript + Vite + Tailwind CSS. Секции в `src/sections/`, сборка `npm run build`.

## Source of truth
1. **GitHub-репозиторий** — основной источник истины для кода, структуры проекта, документации и принятых решений (docs/PRODUCT_AUDIT.md, docs/COMPETITOR_RESEARCH.md, docs/COMPETITORS.md, этот файл, GOALS.md, PLANS.md, PROMPTS.md). При расхождении локальных копий и GitHub — приоритет у GitHub.
2. Подтверждённые материалы пользователя (фото, каталоги, структура `ВСЕ ИЗДЕЛИЯ/`, локальные папки с фотографиями — источник исходных фотографий изделий).
3. Код проекта.
AI-предположения всегда ниже и помечаются UNKNOWN / ASSUMPTION / NEEDS CONFIRMATION.

## Постоянные правила проекта (governance)
- Реальные фотографии изделий имеют приоритет над AI-сгенерированными изображениями; AI-изображения не выдаются за реальные изделия.
- Нельзя изменять конструкцию, внешний вид или характеристики реальных изделий без явного указания пользователя.
- Нельзя выдумывать характеристики, размеры, цены, материалы, технологии, сертификаты, отзывы, награды, гарантии, сроки изготовления, количество клиентов и другие факты.
- Неподтверждённая информация обязана иметь статус UNKNOWN / NEEDS CONFIRMATION / UNVERIFIED; предположение нельзя автоматически превращать в факт.
- При конфликте источников конфликт сохраняется и явно фиксируется; вариант не выбирается самостоятельно.
- Нельзя удалять или объединять изделия только на основании предположения о дубликате.
- Перед существенными изменениями анализировать существующий проект и ранее принятые решения (документы этого файла имеют приоритет над предположениями AI).
- Работа выполняется поэтапно (см. PLANS.md); после каждой значимой фазы — остановка и подтверждение пользователя; автоматический переход между фазами запрещён.
- В исследовательских фазах (аудит, конкурентный анализ, стратегия) запрещено менять сайт, HTML, CSS, JS, фотографии, структуру проекта и Product Master, если текущее задание прямо не разрешает.
- Цель сайта: премиальное позиционирование, доверие к производителю и получение обращений/заявок — не просто демонстрация мебели.
- Конкурентов не копировать буквально: извлекать принципы и адаптировать под проект (см. docs/COMPETITOR_RESEARCH.md, раздел DO NOT COPY).

## Ключевой принцип работы
READ → ANALYZE → PLAN → APPROVAL → IMPLEMENT → TEST → REVIEW.
Не выполнять несколько крупных фаз одновременно. Approval gates: PHASE 2, 3, 4, 5, 7, 8, 12 (см. PLANS.md).

## Контент-правила (обязательно)
- НЕ выдумывать: сертификаты, награды, отзывы, число клиентов, сроки, гарантии, характеристики, историю компании, географию продаж.
- Неподтверждённый факт = UNKNOWN, не публиковать как факт.
- Существующие материалы пользователя приоритетнее предположений AI.

## Фото-правила
- Реальные фото продукции имеют приоритет.
- Не менять конструкцию изделий, не добавлять несуществующие детали.
- Не выдавать AI-generated изображения за реальные изделия.
- Не заменять реальные фото без разрешения пользователя.
- Для веба: JPG, ширина ≤ 1200 px, качество ~80, целевой вес ≤ 150 КБ.

## Design principles
PREMIUM · NATURAL · ARCHITECTURAL · EDITORIAL · TACTILE · RESTRAINED. Тёплая натуральная палитра, Cormorant для заголовков, крупные фото, negative space, сдержанная анимация. Избегать SaaS-визуала, типовых округлых AI-карточек, визуального шума, бессмысленных градиентов и других элементов, снижающих премиальное восприятие.

## Coding principles
- Не переписывать проект целиком без необходимости; менять только затронутое.
- Semantic HTML, responsive (mobile-first), доступность (alt, aria, контраст).
- Переиспользуемые компоненты; данные изделий — в одном месте (`src/sections/Collection.tsx` → при росте вынести в `src/data/products.ts`).

## Testing / Visual QA
После каждого существенного изменения: `npm run build`, проверка в браузере (все изображения грузятся, секции на месте, фильтры работают), скриншот до/после. Не заявлять «готово» без проверки.

## Git rules
- Публикация на GitHub Pages через MCP-шлюз: только текстовые файлы (base64-чанки ≤ 750 КБ, версионированные URL `?v=N`).
- Бинарники через шлюз НЕ передавать (портятся).
- Перед публикацией: пересобрать `_pages3`-пайплайн, сверить чанки, обновлять SHA.

## Stop conditions
- Запрос на выдуманные факты → предложить UNKNOWN-формулировку и спросить данные.
- Публикация без подтверждённого контента.
- Пропуск approval gate.

## Definition of done
Фаза завершена, когда: изменения собраны без ошибок, проверены в браузере, отчёт выдан (COMPLETED / FILES CHANGED / DECISIONS / TESTS / ISSUES / NEXT STEP), пользователь подтвердил результат.
