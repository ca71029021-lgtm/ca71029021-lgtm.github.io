## 1. Стратегическое решение

**Гибридная многостраничная архитектура.** Чистый one-page как единственная структура — отклонён.

Обоснование:
- **Product Master**: 33 публикуемых изделия, 3 категории. One-page с таким объёмом превращается в бесконечную прокрутку; карточки изделий требуют отдельных страниц (ссылки с Авито/мессенджеров, возврат к конкретному изделию).
- **Brand Strategy**: позиционирование «материал первичен», editorial подача — требует пространства и отдельных сцен для материала и изделий.
- **Competitor Research (13 premium-брендов)**: у всех сильных игроков — каталог + отдельная карточка изделия; one-page оставляют только слабые конкуренты.
- **GOALS**: «полный ассортимент без ощущения витрины-призрака» — достижимо только со структурой каталога.

При этом главная страница остаётся **премиальным лендингом** с сценарием DISCOVER → UNDERSTAND → ADMIRE → TRUST → EXPLORE → DESIRE → CONTACT.

## 4. Каталог

### /catalog (обзор)
- Три категории-карточки в editorial-подаче: характерное фото, название, число изделий, диапазон цен.
- Диапазоны (VERIFIED owner): журнальные 8 500–15 000 ₽ · кухонные 28 000–120 000 ₽ · эксклюзивные 65 000–190 000 ₽.

### Категория (например /catalog/kukhonnye-stoly)
- Сетка изделий: крупное фото, рабочее название, ID, размеры (Д×Ш×Т), цена.
- Подача — галерея/lookbook, НЕ marketplace-сетка (см. §12).
- Переход: изделие → карточка; вверху — breadcrumbs (Каталог / Кухонные столы).

### Карточка изделия (/catalog/<категория>/<id>)
| Элемент | Источник / статус |
|---|---|
| Галерея фотографий | фото папки изделия (главное фото — NEEDS CONFIRMATION) |
| Название | рабочее: «Журнальный стол S002» — NEEDS CONFIRMATION (реальные названия UNKNOWN) |
| Product ID | VERIFIED |
| Категория | VERIFIED |
| Размеры (длина×ширина×толщина) | VERIFIED (owner), 33/33 |
| Цена | VERIFIED (owner), 33/33 |
| Материал | алтайский кедр, цельный слэб (общий факт бренда, VERIFIED) |
| Характеристики | только подтверждённые; ничего не придумывать |
| Особенности / детали | UNKNOWN, если нет данных — поле скрыто |
| «Единственный экземпляр» | месседж согласовать (Q4, NEEDS CONFIRMATION) |
| CTA | «Оставить заявку на это изделие» (стратегический вариант) |
| Навигация | related (та же категория), prev/next, возврат в категорию, breadcrumbs |

Если данных нет — UNKNOWN / NEEDS CONFIRMATION, поле не заполняется выдумкой.

## 5. Пользовательские сценарии

**СЦЕНАРИЙ A — эмоциональный (главная):**
Главная → история/материал → /production → избранные изделия → карточка изделия → заявка.

**СЦЕНАРИЙ B — рациональный (каталог):**

**СЦЕНАРИЙ C — прямой вход (не забыть):**
Ссылка из мессенджера/Авито → карточка изделия → заявка. Обязательны: breadcrumbs, prev/next, ссылка на категорию, CTA на карточке без промежуточных шагов.

Любой сценарий: заявка ≤ 2 кликов с любой страницы (SUCCESS CRITERIA из GOALS.md).

## 7. Product discovery

- **Категории — основной и достаточный «фильтр»** (33 изделия, 3 категории).
- **Поиск — не нужен** (ассортимент мал).
- **Фасетные фильтры (цена/размер/материал) — не нужны на старте** (см. спорное решение S6).
- **Сортировка — опционально** «по цене» внутри категории, решается в PHASE 5/7; по умолчанию — editorial-порядок (по ID).
- **Related**: изделия той же категории (последовательные ID); prev/next внутри категории.
- **Возврат в категорию**: breadcrumbs + кнопка «Назад к категории».

Сайт не превращается в интернет-магазин: нет корзины, цен-«от», бейджей скидок, рейтингов.

## 8. Mobile IA (отдельная логика, не уменьшение desktop)

- **Header**: логотип + кнопка заявки; меню — hamburger (4 пункта + CTA).
- **Hero**: сокращённый, один primary CTA, липкая кнопка заявки при прокрутке (sticky CTA).
- **Каталог**: категории — вертикальный список полной ширины; сетка изделий — 1 колонка, крупные фото.
- **Карточка**: swipe-галерея, характеристики под фото, CTA fixed внизу экрана, prev/next — жест/кнопки.
- **Breadcrumbs**: сокращённые (Каталог / Кухонные / S002).
- **Форма заявки**: сокращённая (имя + телефон/e-mail + сообщение), поля с телефонной клавиатурой.
- **Контакты**: tappable phone/e-mail (tel:, mailto:).
- Сценарии A/B сохраняются; приоритет — сценарий B (рациональный) за счёт sticky CTA и коротких путей.

## 9. URL architecture

| Страница | URL |
|---|---|
| Главная | `/` |
| Каталог | `/catalog` |
| Категория | `/catalog/zhurnalnye-stoly` · `/catalog/kukhonnye-stoly` · `/catalog/eksklyuzivnye-stoly` |
| Изделие | `/catalog/zhurnalnye-stoly/s001` … (транслит, lowercase, id в конце) |
| О производстве | `/production` |
| Контакты | `/contacts` |

- Логика: категория — сегмент после /catalog; изделие всегда внутри своей категории (понятная иерархия, related/prev-next в одном сегменте).
- **Техническое замечание (не SEO-реализация)**: GitHub Pages — статический хостинг; красивые URL без .html потребуют либо отдельных каталогов с index.html, либо SPA-роутинга с 404-fallback. Решение — PHASE 8. Сами URL (имена сегментов) здесь утверждаются как структура.

## 12. Premium UX — принципы (чек-лист для PHASE 5+)

**Делаем:** фотография первична; много воздуха; крупная типографика; тактильность материала; editorial/architectural подача; сдержанные CTA.
**Не делаем:** перегруженные карточки; визуальный шум; агрессивные кнопки; marketplace UI; чрезмерные рамки и скругления; бессмысленные бейджи; фальшивые рейтинги и отзывы; цены «от …» без основания.
